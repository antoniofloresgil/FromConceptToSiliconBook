# Dot-product IP release contract

Release 1.1.0 has register ABI 1.0. It is a separately generated release derived
from the locked Lab 10 design, not a replacement for any historical physical
dossier. The engine and MAC are copied byte for byte. The endpoint's fourteen
read/write case labels are generated from `manifest/registers.json` through a
behavioral template. The C header, SV checker constants and register table share
that input. Access policies and field positions are deliberately fixed by this
backend; changing them requires a backend revision and new tests.

## External contracts

The core files are exactly the three paths in `manifest/release.json` under
`rtl/`. The AHB adapter, RAM model, CPU fixture and firmware are integration
collateral outside that set. One rising-edge clock and coordinated active-high
synchronous reset serve CPU, adapter, IP and memory protocol state. Reset does
not erase RAM or roll back a partial result. Isolated IP reset with an outstanding
transaction is unsupported.

The control port is AXI4-Lite, 32-bit data, five-bit byte offsets. AW and W are
buffered independently; R/B responses are retained until acceptance. Descriptor
writes merge byte strobes when idle. CTRL writes and descriptor changes while
busy fail with SLVERR. The generated register table specifies each field. There
is no IP_ID register in ABI 1.0; software selection uses the platform binding and
release manifest, not an invented discovery read.

The DMA port uses 32-bit AXI4, ID 0, one outstanding single-beat INCR transfer,
SIZE=2 and LEN=0. Each N-element job requires 2N reads and two writes. Signed
16-bit samples occupy the low half of each 32-bit source word. Their exact
64-bit sum is written low word first. The result is valid only after DONE with
no ERROR; two word writes are not an atomic 64-bit store. Responses must be
protocol-compliant. There is no hardware watchdog for a target that never replies.

The release admits only the named compact/course profiles: MAX_LENGTH 16/256,
DMA window [0x80008000, 0x8000c000). The underlying RTL permits additional
parameters, but they are outside this qualified package's support matrix. A
START outside the window, with overflow, bad length, misalignment or destination
overlap sets descriptor error without DMA. Source A and B may overlap.

## Integration ownership

AXI simulation has a bus-functional control manager; it is not a second CPU SoC.
The other platform uses the actual pinned RV32 Wally core, an AHB adapter,
simulated shared RAM and direct MExtInt. Its decoder and generated-header firmware
use 0x10080000, leaving Wally's native GPIO address 0x10060000 unassigned by this
device. It does not instantiate the complete uncore, PLIC, coherent caches or
physical memory arbitration. A physical integrator must supply those boundaries.

IRQ is a retained level acknowledged through IRQ_ACK. A new terminal event wins
over simultaneous ACK. Software must transfer buffer ownership and order stores,
START, result reads and ACK. A volatile pointer does not supply that protocol.
The platform must map the DMA window to accessible physical memory and prevent
concurrent writers; this package has no IOMMU or cache-snooping port.

## Supplied and generated views

Supplied: source inventory, register schema, RTL, numerical oracle, stressed AXI
RAM, functional tests, RV32 firmware, Wally export/ELF utility, bounded formal
recipe and example SDC. The generic Yosys netlist is generated by qualification.
The formal recipe proves control at depth 20 and the engine at depth 24, with a
separate reachable DONE witness. Those bounds do not qualify every legal job.

Technology mapping, board constraints, extracted timing, power estimates, LEF,
GDS, scan/ATPG, foundry DRC/LVS and fabrication qualification must identify the
exact generated release and technology. Historical Lab 17/21/22 reports are
examples of the required evidence, not inherited results for this endpoint.

All original packaged executable sources use MIT; the package retains that
license. Wally is an external dependency exported with its own license and
headers. Verify release.json against an independently trusted hash: checksums
detect drift, but do not authenticate an attacker-controlled manifest.
